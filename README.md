# PhyloTreeGUI

PhyloTreeGUI is a tool for visualizing interactive phylogenetic trees.

PhyloTreeGUI takes the phyloXML file generated by CENdetectHOR pipeline as input and produces the following outputs:

1) a BED file containing the annotation of the selected HORs (Higher-Order Repeats) in the centromere sequence;
2) a TXT file describing the composition of the selected HORs, the number of variants found (a variant is discovered when the number of families composing a HOR matches at least 70% of the families of another HOR);
3) a PNG file showing the selected HORs, their composition and the part(s) of the chromosome sequence covered (i.e., bottom-right panel of the GUI)
4) a set of TXT files illustrating the monomers belonging to the families that form the selected HORs.

PhyloTreeGUI can be launched from a terminal:

python main.py [--path <path/to/dir/with/phylo/xml/files>] [--unit_length <int_val>] [--folder <dir/where/to/save/output/files>] [--fullscreen]

Arguments within squared brackets are optional and can be used to specify:

1) path to the directory containing the phyloXML files (default is the current directory);
2) whether the HOR tree is shown with unit branch lengths (default is 0, i.e. floating-point lengths will be used);
3) folder/directory where output files will be stored (default is the current directory);
4) whether PhyloTreeGUI has to be run in full-screen mode (default is false).

When the GUI is opened, the user can see a drop-down menu on the upper-right corner, which shows the list of phyloXML files in the input folder that can be selected. The GUI allows to perform different actions through the following buttons:

1) LoadFile
2) PlotTree
3) SelectDepth
4) ShowData
5) GetOutput
6) CloseGaps
7) Reset
8) ShowSimilarity

After selecting a phyloXML file from the drop-down menu, the user shall click on the “LoadFile” button in order to load all the information contained in the file (i.e., the monomer and the HOR trees). Then, the user can see the HOR tree by pressing the “PlotTree” button: it consists of several branches originating from the root and containing circles/nodes, which indicate the HORs found. The HOR tree is interactive: the nodes are clickable and can be used to select one or more HORs, which will assume a different color. Moreover, the possibility to automatically select all the HORs at a given depth from the root of the HOR tree has been provided through the “SelectDepth” button: once the user selects a HOR at a given depth, all the HORs at the same depth will be selected. As an alternative, if the user wants to select HORs based on their similarity, the GUI has a dedicated button called “ShowSimilarity”: if pressed, a drop-down menu containing all the similarity levels appear. The user can select the desired similarity and the HORs corresponding to that value are automatically covered. If the user chooses the latter option, pressing the “SelectDepth” is useless (actually a popup message is raised, see below). Once the user has selected a set of HORs to analyze, he/she can visualize the structure of the HORs (i.e., the families of monomers composing each of them), the locations of the HORs in the chromosome sequence and the monomer tree by clicking the “ShowData” button. In particular, a new panel appears on the bottom right corner of the PhyloTreeGUI, displaying each selected HOR (identified by the same color as the clicked node) along with a schematic representation of its composition. This schematic is composed of N colored blocks, where N corresponds to the number of clades composing the HOR, and each color is specific to a clade. The same clade-specific colors also appear in the monomer tree (displayed on the left side of the PhyloTreeGUI) to distinguish all the branches involved in the HORs. An additional section in the same panel shows a grey bar representing the input sequence, with colored portions indicating the exact location of the selected HOR. In order to save data related to the selected HORs, the user should click the “GetOutput” button that is responsible for the generation of the output files described above. Moreover, a check on the sequence coverage is made by taking into account the threshold level (default value is 75%, but the user can specify a different value in the “Desired coverage” box, which should be in the range [0,100]%). If the coverage does not reach the threshold, a pop-up message is shown, which displays the current coverage after selection. In order to enhance sequence coverage, the user can click the “CloseGaps” button, which is responsible for the discovery of HORs that must be added. This is an iterative process that ends when the expected coverage level has been reached. After the “CloseGaps” method performs its computation, the newly added HOR(s) is(are) colored in the HOR tree and the user can visualize how the sequence coverage changed by clicking the “ShowData” button. The “Reset” button allows to reset the GUI: it clears the selection of the HORs in the HOR tree and removes all the other objects that have been visualized (e.g., the families of monomers constituting the selected HORs, their locations in the chromosome sequence and the monomer tree). The user can make a new selection of different HORs and perform a different analysis by repeating the steps previously described.

If the user decides to load a different phyloXML file (drop-down menu), the window containing the previous HOR tree will be cleaned. Finally, the tool shows pop-up error messages when the user performs one of the following invalid operations:

1) the user clicks on the “LoadFile” button before having selected a phyloXML from the drop-down menu;
2) the user presses the “PlotTree” button before having loaded the phyloXML file through the “LoadFile” button;
3) the user clicks on the “ShowData” button before having selected one or more HORs from the HOR tree;
4) the user presses the “SelectDepth” button after having clicked on the “ShowSimilarity” button.
